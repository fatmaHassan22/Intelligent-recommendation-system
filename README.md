# تشغيل مشروع الدعم الأكاديمي على Windows — نسخة الفريق

هذه نسخة مستقلة من الكود والبيانات الأكاديمية. لا تحتوي على حسابات طالبات أو كلمات مرور أو جلسات أو محادثات. أنشئي حسابك من واجهة التطبيق بعد التشغيل.

يمكن نقل ZIP بفلاشة أو إرساله دون اتصال. **تثبيت البرامج والحزم أول مرة يحتاج إنترنت**؛ لأن node_modules وملفات البرامج غير مرفقة. خدمات Gemini وMoodle وPush معطلة افتراضيًا ولا تحتاج مفاتيح للتشغيل الأساسي. لا يوجد نشر سحابي ضمن هذه الخطوات.

## 1. البرامج المطلوبة

- Windows، وPowerShell الموجود معه.
- Node.js بإصدار 22.12 أو أحدث متوافق مع المشروع (يفضل 22.x)، مع npm.
- MySQL Server 8 محلي يعمل على 127.0.0.1 والمنفذ 3306. Workbench اختياري وليس بديلًا عن Server. احتفظي بكلمة مرور root الخاصة بجهازك.
- pnpm 10.18.3. بعد تثبيت Node افتحي PowerShell ونفذي:

```powershell
npm install --global pnpm@10.18.3
node --version
pnpm --version
```

## 2. فك الضغط وتثبيت الحزم

اضغطي بزر الفأرة الأيمن على ZIP ثم Extract All. افتحي مجلد FYP2-Team-Share الذي يحتوي README وbackend وfrontend. من شريط عنوان المجلد اكتبي powershell واضغطي Enter. نفذي:

```powershell
pnpm --dir backend install --frozen-lockfile
pnpm --dir frontend install --frozen-lockfile
```

انتظري اكتمال الأمرين. لا تنسخي node_modules من جهاز آخر.

## 3. إنشاء قاعدة جديدة واستيرادها وإعداد الاتصال

**هذه الخطوة على جهاز الزميلة فقط.** أداة الإعداد تتصل حصريًا بـ MySQL المحلي، ولا تستخدم Aiven أو أي اتصال سحابي. تنشئ قاعدة جديدة، وتستورد 17 جدولًا أكاديميًا، وتطبق ترحيلات backend لإنشاء جداول الطالبات الفارغة وتعريفات الإنجازات العامة. ثم تنشئ حساب MySQL للتطبيق، له قراءة فقط للجداول الأكاديمية وصلاحيات محددة للجداول الأخرى.

من نافذة PowerShell السابقة، نفذي:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\team-tools\setup-local.ps1
```

هذا التجاوز يخص العملية الحالية فقط. إذا منعت سياسة الجامعة تشغيل السكريبت، لا تغيري سياسة الجهاز؛ تواصلي مع مسؤولة الجهاز.

عند طلب اسم القاعدة اكتبي مثلًا **academic_team_demo**. يجب أن يبدأ بـ academic_team_. عند طلب كلمة المرور أدخلي كلمة مرور root المحلية الخاصة بك؛ لن تظهر أثناء الكتابة. لا تستخدمي كلمة مرور صاحبة المشروع.

الأداة **ترفض قاعدة موجودة حتى لو كانت فارغة**، وترفض الكتابة فوق ملفات .env موجودة. لا تحذف ولا تعيد ضبط أي قاعدة. إذا فشلت بعد إنشاء القاعدة، فقد تبقى قاعدة جديدة جزئية؛ توقفي وشاركي رسالة الخطأ الآمنة مع مسؤولة المشروع، دون إرسال .env. لا تعيدي استخدامها ولا تشغلي أوامر حذف لإصلاحها.

بعد النجاح تُنشأ backend/.env وfrontend/.env **محليًا فقط**، بسر عشوائي جديد للجلسات/CSRF وكلمة مرور عشوائية لحساب التطبيق. كلمة مرور root لا تحفظ في الملفات. ملفات .env.example المرفقة تحتوي أسماء ومتغيرات بديلة فقط؛ لا تنسخيها فوق الإعداد الذي تولده الأداة، فهي ليست إعدادًا جاهزًا للتشغيل.

## 4. تشغيل Backend

في النافذة الأولى، من مجلد المشروع:

```powershell
pnpm --dir backend dev
```

اتركي النافذة مفتوحة. للتحقق افتحي http://127.0.0.1:3000/health في المتصفح.

## 5. تشغيل Frontend

افتحي نافذة PowerShell ثانية من مجلد المشروع ونفذي:

```powershell
pnpm --dir frontend dev
```

افتحي **http://127.0.0.1:5173**. استخدمي هذا العنوان باستمرار؛ الإعداد الافتراضي لـ CORS يستخدم 127.0.0.1. سجلي حسابًا جديدًا في التطبيق. الحسابات القديمة غير مرفقة.

لإيقاف التطبيق اضغطي Ctrl+C في النافذتين. تبقى البيانات في MySQL على جهازك، وأعيدي تشغيل الأمرين لاحقًا دون إعادة الإعداد أو الاستيراد. لا تحتاجين تشغيل worker منفصل؛ المهام المحلية الأساسية تعمل داخل backend. تكامل Moodle وPush وGemini يحتاج إعدادًا منفصلًا ومصرحًا به لاحقًا.

## مشاكل شائعة

- فشل الاتصال: تأكدي من تشغيل خدمة MySQL Server محليًا على 3306 ومن كلمة مرور root. لا تستبدليها بعنوان قاعدة سحابية.
- node أو pnpm غير معروف: أغلقي PowerShell وافتحيه بعد تثبيت البرامج.
- المنفذ 3000 أو 5173 مستخدم: أوقفي نسختك السابقة من التطبيق، ثم أعيدي التشغيل. لا توقفي برامج الآخرين دون تنسيق.
- مشكلة تسجيل الدخول: افتحي 127.0.0.1:5173، وتأكدي من بقاء backend يعمل. لا ترسلي cookies أو .env في لقطات الشاشة.
- لا تشغلي test:prepare أو سكريبتات phase* أو provision:local أو migrate على قواعد قائمة لمجرد حل مشكلة تشغيل. التعليمات أعلاه تغني عنها للإعداد الأول.

## الاستيراد اليدوي الاختياري — للمشرفة التقنية

الطريقة الأسهل هي أداة الإعداد. إن لم تستخدميها، أنشئي قاعدة **جديدة وفارغة** محليًا، بترميز utf8mb4 وcollation utf8mb4_0900_as_cs. من Workbench داخل اتصالك المحلي اختاري File > Open SQL Script وافتحي database/academic-curriculum.sql، واختاري القاعدة الجديدة بالنقر المزدوج عليها ثم نفذي السكريبت كاملًا. لا تستورديه إلى قاعدة مستخدمة.

الملف يجمع البنية والبيانات لـ17 جدولًا فقط؛ لا يتضمن CREATE DATABASE أو USE أو DROP أو بيانات حسابات. بعدها يجب إعداد backend/.env.migrate.local **على جهازك** بحساب إداري للقاعدة الجديدة، وDB_HOST=127.0.0.1 وDB_PORT=3306 وDB_NAME باسم القاعدة الجديدة، وCSRF_SECRET عشوائي لا يقل عن32 حرفًا، وCORS_ORIGINS=http://127.0.0.1:5173 وNODE_ENV=development، ثم:

```powershell
pnpm --dir backend migrate
```

بعدها أنشئي حساب التطبيق بصلاحيات مماثلة لأداة team-tools/setup-local.mjs، واكتبي backend/.env بقيمه المحلية. لا تشغلي التطبيق يوميًا بحساب root، ولا تشغلي أداة الإعداد التلقائي بعد الاستيراد اليدوي؛ سترفض القاعدة الموجودة.

## محتويات النسخة والتحقق

- backend/src وfrontend/src: الكود الكامل، مع الاختبارات والملفات العامة والخطوط المحلية.
- package.json وpnpm-lock.yaml وملفات TypeScript/Vite وDocker وscripts والترحيلات: مرفقة.
- database/academic-curriculum.sql: التصدير الأكاديمي الحالي؛ database/manifest.json: عدد الصفوف لكل جدول وبصمة SHA-256.
- data/seed.sql: نفس لقطة البيانات الأكاديمية بصيغة بيانات فقط لدعم bootstrap الخاص بملفات Docker الموجودة؛ لا تعيدي استيراده بعد التصدير الكامل.
- team-tools: إعداد Windows الآمن للقاعدة الجديدة. هذا هو مسار التشغيل الموصى به للزميلات.
- deploy: إعدادات إنتاج اختيارية للمراجعة، تتطلب أسرارًا وشهادات تولد على الجهاز؛ ليست جاهزة للتشغيل مباشرة بقيم .example. ليست مطلوبة للتشغيل المحلي أعلاه.
- SECURITY-AND-VERIFICATION.md: حدود التحقق وملاحظات البيانات. FILE-MANIFEST.json: بصمات ملفات النسخة.

لا توجد node_modules أو dist أو .git أو قواعد MySQL الخام أو نسخ احتياطية أو ملفات .env فعلية في ZIP. توجد في الكود اختبارات وعبارات إنشاء جداول المستخدمين؛ **هذه تعريفات برمجية وليست سجلات مستخدمين مصدرة**.

## البناء والاختبارات الاختيارية

```powershell
pnpm --dir backend build
pnpm --dir frontend build
pnpm --dir frontend typecheck
pnpm --dir frontend test
```

backend/test وtest:integration يتطلبان إعداد بيئة اختبارات منفصلة؛ لا تشغليهما باستخدام بيانات قاعدة التطوير أو قاعدة قائمة. لم تُشغل اختبارات التكامل أو استيراد تجريبي أثناء تجهيز ZIP حفاظًا على قواعد البيانات الأصلية. بعد التثبيت يمكن تشغيل backend المبني بـ pnpm --dir backend start؛ واجهة التطوير تبقى بالأمر الوارد أعلاه.

لا تعيدي إرسال النسخة بعد تشغيلها دون تنظيف ملفات .env والبيانات الجديدة والمخرجات والاعتمادات. الأفضل مشاركة ZIP الأصلي كما هو.
